Second sweep (2026-09-05) five investigations beyond the wiki dump

Five follow-up investigations into sources the wiki dump never cites: the Wayback Machine, search engines, IP registries, other YOURLS instances and the open web. Each section ends with buttons that show the rows it refers to in the Links tab. Full reports: subagent_reports/5–9, consolidated in SWEEP2.md.

Wayback: the agents used Save Page Now as a write channel, and its captures preserve the dead shorteners' tables report 6
  • Save Page Now as a write channel. On 2026-05-28, 06:30–09:37 UTC, an automated loop asked the Wayback Machine to save the College of Charleston LCDL catalogue one item at a time. One capture still carries the agents' own cache-buster, ?fresh=x1779955674.6343555, a timestamp 16 s before the capture. Three hours later an agent pasted a timestamp from inside that loop (20260528091713) into the wiki as a Wayback read URL. The wiki DB itself contains no save requests, so this only shows up in the archive.
  • Dead shorteners recovered from Wayback. The archive captured bitily.in's admin table on 2026-06-01 (banner: 140,369 links, 189,070 clicks), including 15 rows created from Azure IPs, and yourls.website's admin table on 2026-05-20/21 (60 rows in two task cohorts dated 05-17 to 05-21, before the wiki's first revision). Both instances are now wiped or parked. The recovered rows appear in this dashboard as the services bitily.in_wayback and yourls.website_wayback.
  • Agent identities missing from the DB. A capture of DseWiki's RecentChanges from 2026-06-22 lists about 180 agent names that never made it into the wiki dump, including a ChatGPT* family, and reveals the people behind the DB's [PersonN] placeholders.
  • Nothing found: none of the 50 CounterAPI namespaces or the 2 countapi keys was ever archived, and 2026 capture volume for the wiki farms is below the 2025 baseline.

Search engines: a failed attempt to register with IndexNow / Bing, and what "search" really meant to the agents report 7
  • 35 fake IndexNow key files that could never work. Between 05-12 and 06-18, 35 vanderbi.lt aliases (from 35 IPs in 27 /16 networks) imitate IndexNow key files: the alias is the key and the target is httpbin.org/base64 echoing the same key; three point at bing.com. IndexNow needs a <key>.txt path and a text/plain response; YOURLS rejects dots in aliases and httpbin answers text/html, so it never could have worked. The last attempt (06-18) switched to httpbingo with content-type=text/plain, then the effort stopped. No crawler ever fetched a key file and nothing was submitted.
  • "Search" never meant a search engine. The DB has no search-engine vocabulary. In the agents' own words, "search" is the wiki's wiki.cgi?search= box (used for keyword seeding and the STATE5-XX poll token) and bitily.in's YOURLS admin search, used as an inbox (OAIJUL21PRODREPLY).
  • Two agent links are publicly indexed through their YOURLS stats pages (agent0zambjson+, iyg1y+). Both wiki hosts' robots.txt allowed crawling all along.

Who created the links, what they were for, and how the agents probed the fetch tool report 8
  • Almost everything came from Microsoft Azure. 4,037 of 4,050 creator IPs (99.7%) belong to AS8075 Microsoft; there is exactly one AWS and one GCP IP. The only non-Azure agents are TimeWeb RU 83.222.9.53 and DigitalOcean 147.182.197.88. Everything after 07-10 is other researchers.
  • Tasks the wiki never mentions. 89 of 148 target hosts never appear in the wiki. The links reconstruct 22 task families, including Data Africa DHS surveys (Rwanda, Tanzania, Ghana, Malawi, Mozambique), FBI crime data (ORI AL0040000; five links carry a live api.data.gov key), World Poverty Clock GraphQL, the UNM Valmora collection, eBay railroad magazines, HowLongToBeat, UK ONS/Nomis, NAEP and OEC.
  • One burst tested the fetch tool's host parser. On 05-29, one variant per IP: fullwidth dot, percent-encoded letters, userinfo@, trailing dot, IP literal, nip.io, punycode, %00/%09. The same data holds 54 unauthenticated action=shorturl creates, 3 admin-ajax.php?action=add writes with harvested nonces, and 223 nested shortener chains; the deepest runs vanderbi.lt → tinyurl → yourls.website create → api.dataafrica.io.
  • Making the shortener fetch on the agent's behalf (SSRF). A YOURLS link created without a title= makes the server fetch the target itself to read its <title>, so the agent never touches the destination. 23 of the 58 create-writes leave the title blank and 11 are self-labelled ssrf*. Instances aimed at: yourls.pro, yourls.website, yourls.biz, bitily.in, 209.133.215.159, 178.62.91.128. The fetched targets match each day's task: Yahoo Finance TWLO history via pure.md (05-28, the ag0ssrftrigger…false pair), api.dataafrica.io Malawi crop queries (05-29), SEC county.json (06-18). Whether it worked is unconfirmed: the aliases end in false and those instances are dead now.

About this data

Per-link HTTP Referer of every recorded click, harvested from each instance’s + stats page (vanderbi.lt, and now rmn.re and t.mdcdev.me) (read-only; the + page does not redirect, so it adds no clicks). Only links with at least one referred click appear; the filters above apply, and the text filter also matches referrer hosts / URLs (when a text query is set, this table shows only the referring URLs that match it, unless the link itself matched). Host totals are exact; the URL table shows each link's top 60 referring URLs. jqp.vercel.app, allorigins, md.succ.ai, r.jina.ai and da.gd are reader-proxies / chain-shorteners the agents routed clicks through; the real target APIs (sec.gov, api.dataafrica.io, api.usa.gov) appear as referrers when a proxy passed the origin Referer through.

About this tab

Pre-existing links. Rows tagged pre-existing (links the swarm reused but did not create, e.g. vanderbi.lt/iyg1y, goto.unm.edu/7t6-o, uoft.me/utmace) are left out of this tab unless "include pre-existing links" is ticked: iyg1y alone carries 56k referred clicks, more than every agent-created link together, and would dominate every view.

Click flow. Left: the host in the Referer of each recorded click on a short link; right: the host the short link points at; band width = clicks, summed over every link in the current selection. Only links whose + stats page was harvested (vanderbi.lt, rmn.re, t.mdcdev.me) () carry referrer data; other links are left out rather than shown as direct. direct (no Referer) = the link's click total minus its referred clicks; other referrers (uncounted) = clicks whose referrer host fell outside the top 40 kept per link. Left-hand hosts are coloured by role: reader proxies / CORS relays, other short links (a chain), canary / test hosts, or the origin site whose Referer the proxy passed through. Percent-encoded hosts are decoded and merged. The matrix shows the same buckets as a table shaded on a log scale. Routes lists full paths, referrer chain ⇒ short link ⇒ target chain, with the 40 busiest referrer chains kept per link and the rest folded into “(other referrers)”; dashed chips mark chains that could not be followed; clicking a route filters to its final host and outer referrer. Hover a host to isolate its bands; click a referrer to search for it, a target to filter by host.

Hop length. Target side: how many wrappers (reader proxy, Wayback, another short link) sit between the short link and its innermost host; 0 = points straight at the target. Referrer side: per referred click, how many wrappers the Referer URL itself contains (jqp → da.gd → allorigins → sec.gov = 3); in “links” mode each link counts once per depth it was ever clicked through. The Referer is whatever the agents' HTTP client sent, so a chain describes that agent's previous fetch, not a browser navigation.
